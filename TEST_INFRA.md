## 1. Overview & Objectives

This test infrastructure implements a comprehensive, automated, 4-tier End-to-End (E2E) verification suite designed to validate the **AI Sanitization & Script Archiving** project for the PEAK modpack.

The test suite ensures:
1. **Zero AI Trace Remnants**: Complete eradication of all AI coding agent attributions (`Antigravity`), LLM model names (`ChatGPT`, `Claude`, `OpenAI`), sequential prompt iteration notes (`Prompt [0-9]`), conversational commentary (`per user request`, `The user wants to`), internal monologues (`# Wait, KubeJS`), Spanish automated generation headers, and developer environment path leakage across `minecraft/`.
2. **Maintenance Script Archiving**: 100% of the 24 standalone Python diagnostic/repair utilities are moved from `minecraft/` into `scrapped_tools/` at the project root with zero Python files remaining in `minecraft/`.
3. **100% Code & Asset Functional Preservation**: Strict syntactic, structural, and functional equivalence of all 64 KubeJS scripts (`server_scripts`, `client_scripts`, `startup_scripts`), custom Blockbench 3D block models (`flowerbed_*.json`), and FTB Quests localization (`en_us.snbt`).

## 3. Test Tier Architecture

### Tier 1: Feature Coverage & Core Acceptance Criteria
- **`test_01_no_python_files_remain_in_minecraft`**: Recursively audits `minecraft/` to assert that zero `.py` files exist in the tree.
- **`test_02_all_python_scripts_archived_in_scrapped_tools`**: Verifies that `scrapped_tools/` exists and contains all 24 relocated Python maintenance utilities.
- **`test_03_zero_banned_ai_signatures_in_minecraft`**: Performs regex scanning across all readable files in `minecraft/` against the banned AI pattern catalogue.
- **`test_04_all_kubejs_javascript_files_parse_cleanly`**: Executes `node --check` across all 64 KubeJS scripts to guarantee zero syntax or parsing errors.
- **`test_05_all_minecraft_json_files_parse_cleanly`**: Parses all JSON files across assets, data, worldgen, and configs using BOM-safe and JSON5-tolerant validation.
- **`test_06_blockbench_flowerbed_model_credits_cleaned`**: Validates `flowerbed_1.json` through `flowerbed_4.json` ensuring standard `"Made with Blockbench"` credit without AI mentions.

### Tier 2: Boundary & Corner Cases
- **`test_01_case_insensitive_regex_variations`**: Tests casing permutations (`aNtIgRaViTy`, `CHATGPT`, `openAI`, `pRoMpT 2`, `AUTO-GENERATED BY`, etc.).
- **`test_02_whitelist_preservation_for_ingame_antigravity`**: Validates whitelist logic to ensure legitimate in-game spell/status effects (`effect.irons_spellbooks.antigravity`) are preserved and not flagged.
- **`test_03_multiline_and_block_comment_handling`**: Validates detection of AI signatures inside multiline `/* ... */` comment blocks.
- **`test_04_comments_inside_string_literals_are_not_stripped`**: Verifies that URL strings or text containing `//` or `/*` inside string quotes remain untouched.
- **`test_05_non_ascii_and_unicode_emoji_resilience`**: Verifies handling of UTF-8 emojis (`🌟`, `⚔️`, `🔮`, `🍞`), em-dashes (`—`), arrows (`→`), and legacy mojibake without runtime crashes.
- **`test_06_empty_file_and_whitespace_only_handling`**: Validates resilience on 0-byte or whitespace-only files.
- **`test_07_json_structure_integrity_detection`**: Verifies that malformed JSON structures (unquoted keys, missing brackets) are correctly caught.

### Tier 3: Cross-Feature Combinations & Functional Preservation
- **`test_01_kubejs_scripts_retain_all_functional_event_listeners`**: Asserts that critical KubeJS event listeners (`ServerEvents.recipes`, `ServerEvents.tags`, `ItemEvents.modification`, `StartupEvents.registry`) are retained across the suite.
- **`test_02_tag_unifications_script_integrity`**: Extracts functional tokens from `00_tags.js` to ensure screwdriver tag mappings (`c:tools/screwdriver`, `immersiveengineering:screwdriver`, `tfmg:screwdriver`) and rune tags (`kubejs:irons_runes`) are 100% intact.
- **`test_03_sequenced_assembly_datapack_recipes_integrity`**: Extracts functional tokens from `20_fixed_datapacks.js` to ensure sequenced assembly recipe builders and transitional items are intact.
- **`test_04_create_and_pneumaticcraft_progression_gates_integrity`**: Verifies progression gate recipes in `02_create_era_gates.js` and `03_pneumatic_mekanism_gates.js`.
- **`test_05_flowerbed_3d_geometry_and_texture_preservation`**: Deep inspection of all 4 flowerbed block models: verifies `ambientocclusion: false`, texture mappings (`particle`, `flowerbed`, `stem`), and element cube definitions (7, 3, 5, 5 elements respectively with precise coordinates, rotations, and UV faces).
- **`test_06_custom_items_startup_registry_intact`**: Verifies that `custom_items.js` retains all item registration calls (`event.create(...)`) for custom items (`frozen_heart_core`, `primordial_core`, `culinary_singularity`, etc.).

### Tier 4: Real-World Workload Scenarios
- **`test_01_full_kubejs_subsystem_verification`**: Exhaustive scan across all 170+ files in `minecraft/kubejs/` for zero AI violations and syntax integrity.
- **`test_02_deep_ast_parsing_and_syntax_of_all_js_scripts`**: Node.js AST parsing of all 64 JavaScript files.
- **`test_03_ftbquests_snbt_localization_and_zero_ai_check`**: Full lexing and parsing of `config/ftbquests/quests/lang/en_us.snbt` (3,310+ lines), validating 682 quest entries and zero AI remnants.
- **`test_04_mod_configs_integrity_and_cleanliness`**: Deep scan across 130+ mod configuration files in `config/` and `defaultconfigs/`.

## 4. Execution Guide & CLI Usage

### Running All Tests
```bash
python tests/e2e_test_runner.py
# or
python tests/run_all_tests.py
```

### Running Specific Tiers
```bash
# Run Tier 1 only (Feature Coverage)
python tests/e2e_test_runner.py --tier 1

# Run Tier 2 only (Boundary & Corner Cases)
python tests/e2e_test_runner.py --tier 2

# Run Tier 3 only (Functional Preservation)
python tests/e2e_test_runner.py --tier 3

# Run Tier 4 only (Real-World Workloads)
python tests/e2e_test_runner.py --tier 4
```

### CLI Options
- `--tier {1,2,3,4,all}`: Select specific tier to run (default: `all`).
- `--json-report <path>`: Output execution report to JSON (default: `tests/test_report.json`).
- `--no-color`: Disable colored ANSI terminal output.
- `-v, --verbose`: Enable verbose test output.

### Exit Codes
- `0`: All executed tests passed with zero failures or errors.
- `1`: One or more tests failed or encountered errors.
