# PEAK Modpack - Development Guidelines & Code Cleanliness Rules

## 1. Strict Prohibition of AI Attribution and Meta-Comments
- **NEVER** include comments, headers, or metadata attributing code or assets to AI, LLMs, Antigravity, or ChatGPT (e.g., `// Auto-generated by Antigravity`, `"credit": "Made with Blockbench / Fixed by Antigravity"`).
- **NEVER** include references to prompt iterations, stages, or development phases (e.g., `// handled in prompt 2`, `// Will be refined in Prompt 4`).
- **NEVER** include dialogue remnants or conversational references to the user in code comments (e.g., `// (Recipe removed per user request)`, `// The user wants to force...`, `# Wait, KubeJS 1.21 NeoForge expects...`).
- All code comments must be strictly technical, concise, neutral, and professional (e.g., `// Tag unifications`, `// Recipe balance adjustments`).

## 2. Directory Structure & Script Cleanliness
- **NEVER** create standalone Python utility scripts (`.py`), temporary debug scripts, or scratch files directly inside the `minecraft/` directory.
- All automation, maintenance, and diagnostic scripts must reside strictly in `scrapped_tools/` or at the repository root.
- The `minecraft/` folder must contain only valid game files, mod configurations, resource packs, datapacks, and native KubeJS scripts (`.js`).

## 3. KubeJS & Modding Best Practices (NeoForge 1.21.1)
- Use standard KubeJS 1.21 events (`ServerEvents.recipes`, `ServerEvents.tags`, etc.).
- Target Data Components via `.withComponents()` instead of legacy `.withNBT()`.
- Ensure all scripts and JSON files compile cleanly with zero syntax errors.
- Never delete or modify functional game logic without explicit verification.
